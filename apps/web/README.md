# @arena/web

The Arena product host (Work Order B001): a **Next.js App Router**
application. The first-run landing (`/`) is the default product
experience — a calm three-step introduction with the single primary CTA
*Explore a capability* — and the core route matrix
(`/cases`, `/bodies`, `/research`, `/marketplace`, `/operations`,
`/settings`) renders as structural stubs with real loading/empty/error
states from the Arena design system (`@arena/ui-platform`).

The legacy engineering surfaces (node:http console, workbench,
marketplaces) are kept intact and tested — they are no longer the default
entry point but remain one script away (see below).

## Commands

```bash
pnpm dev               # next dev        (product host on :3000)
pnpm build             # next build      (default output — Vercel-compatible)
pnpm start             # next start      (serve the production build)
pnpm typecheck         # tsc --noEmit    (app tree + legacy console/workbench/marketplace)
pnpm lint              # eslint .        (local flat config, .ts + .tsx)
pnpm test              # vitest run      (app smoke tests + all legacy suites)

# legacy engineering surfaces (still green, no longer the default):
pnpm start:console               # node:http control console on :8787
pnpm start:workbench             # expert workbench on :8788
pnpm start:marketplace           # artifact marketplace on :8789
pnpm start:marketplace:experts   # expert marketplace on :8791
pnpm selfcheck                   # legacy envelope selfcheck (src/main.ts)
```

## Vercel

- **Build command:** `next build` (default; no custom output mode).
- **Output:** default `.next` build.
- **Root directory:** the app lives in `apps/web`. Recommended setup:
  import the repository root and set the Vercel project's *Root Directory*
  to `apps/web` (so the workspace symlinks and `pnpm-lock.yaml` at the
  repo root are respected). Setting the repo root as the Vercel project
  root *without* the Root Directory setting is not supported.
- **Environment variables:** none required at build time. This work order
  adds no auth, no analytics and no provider credentials (those arrive
  with B004/B014/B015).

## Layout

```
src/app/            App Router tree (layout, landing, stub routes, quality gates)
src/app/_lib/       Colocated non-route modules (landing view, route stub, nav)
src/console/        Legacy control console (A018)      — start:console
src/workbench/      Legacy expert workbench (A017)     — start:workbench
src/marketplace/    Legacy marketplaces (A031/A032)    — start:marketplace*
src/main.ts         Legacy envelope selfcheck (A001)   — exercised by tests
```

## Notes

- `next build` has build-time ESLint disabled (`eslint.ignoreDuringBuilds`)
  because the verification battery runs `pnpm lint` as its own step with
  the house flat config (`eslint.config.mjs`); `eslint-config-next` is
  intentionally not used (frozen dependency policy, version-conflict
  risk).
- `next-env.d.ts` is generated by Next.js and committed (per Next
  convention); `tsconfig.json` already carries every option `next build`
  requires, so builds do not mutate it.
- TypeScript checks the legacy `src/console`, `src/workbench`,
  `src/marketplace` and `src/main.ts` trees together with the App Router
  tree (single `tsc --noEmit`).
