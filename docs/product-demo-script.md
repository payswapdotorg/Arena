# Arena Product Demo Script D1.0

## Goal

Give a new user a meaningful first session without requiring provider credentials or prior Arena knowledge.

## Demo scenario

A reference Software Engineer Body has a capability gap:
the agent can implement isolated changes but struggles with a repository-level multi-file task.

### Scene 1 — Welcome

Hero:
“Find what your agent cannot do yet.”

User enters Demo workspace.

### Scene 2 — Capability Case

Show:
- observed failure;
- evidence;
- affected Body;
- target capability;
- unknowns.

Primary action:
“Develop this capability.”

### Scene 3 — Task

Show compiled TaskSpec:
- objective;
- constraints;
- environment;
- verifier;
- expected evidence.

Primary action:
“Enter the workspace.”

### Scene 4 — Environment

Show the deterministic software-engineering environment.

User can replay the agent/expert path.

A prominent label:
“Simulation / replay — not a live production mutation.”

### Scene 5 — Trajectory

Timeline distinguishes:
- observation;
- action;
- tool call;
- error;
- recovery;
- outcome.

### Scene 6 — Evaluation / Verification

Show:
- evaluator criteria;
- evaluation result;
- verified evidence;
- unknown causes, if any.

### Scene 7 — Agent Body

Show:
Body:
- role;
- skills;
- procedures;
- knowledge;
- tools;
- verification.

Then:
Possession:
- Body v1;
- Cognitive Substrate;
- runtime;
- environment.

The visual message is:
“Same body, different cognitive substrates.”

### Scene 8 — Certification

Show the exact certified composition:
Body × Substrate × Environment × Runtime × Certification Suite.

Do not present certification as a property of the raw model.

### Scene 9 — Release

Show the versioned Body release, provenance, compatibility and usage entitlement.

### Scene 10 — Role switch

Switch:
Owner -> Agent Builder -> Researcher -> Operator.

The same case remains selected, but the primary action and inspector change.

End on:
“Now build or improve your own capability.”

## Demo quality bar

The demo must be:
- deterministic;
- resettable;
- clearly labelled;
- fast enough for first-session use;
- free of external model/provider calls;
- representative of the actual operational architecture.
