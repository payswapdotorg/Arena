# Arena Accessibility Statement A11Y1.0

**Last Updated:** October 2026  
**Status:** In Development  
**Conformance Level:** WCAG 2.1 AA (Target)

## Commitment to Accessibility

Arena is committed to providing an accessible and inclusive experience for all users, regardless of ability. We recognize that accessibility is not just a compliance requirement but a fundamental aspect of product design that enables participation from diverse users across our platform.

## Scope

This accessibility statement applies to the Arena web application, which includes:

- Role-aware interfaces for Owner, Expert, Builder, Researcher, and Operator workflows
- Capability development and management tools
- Expert workbenches and evaluation systems
- Agent Body Studio and possession management
- Environment replay and trajectory inspection
- Marketplace and artifact discovery
- Operations and monitoring dashboards

## Accessibility Features

### Keyboard Navigation
- Full keyboard support for all interactive elements
- Logical tab order through interfaces
- Escape key support for modal dialogs and dropdown menus
- Focus indicators visible at all times
- Skip navigation links for screen reader users

### Screen Reader Support
- Semantic HTML structure with proper heading hierarchy
- ARIA landmarks for navigation (main, navigation, complementary, contentinfo)
- Form labels and descriptions for all input fields
- Live regions for dynamic content updates
- Proper ARIA roles and states

### Visual Design
- Sufficient color contrast (minimum 4.5:1 for normal text)
- Responsive design that adapts to different viewport sizes
- Touch targets of at least 44x44 pixels for mobile interactions
- Clear visual focus indicators
- Reduced motion support for users with vestibular disorders

### Mobile Accessibility
- Responsive layouts optimized for touch interaction
- Bottom navigation for mobile devices
- Touch-friendly controls with adequate spacing
- Horizontal scrolling for wide content tables
- Optimized font sizes for readability

## Known Limitations

While we strive for full accessibility, we acknowledge the following limitations:

1. **Complex Interfaces**: Some advanced workflows may present challenges for users with certain disabilities
2. **Real-time Updates**: Live content updates may occasionally be challenging for screen reader users
3. **Mobile Gestures**: Some interactions rely on gestures that may not be accessible to all users
