# ADR-P001-09 — The three unmounted/unintegrated web feature surfaces are named; disposition delegated to P005

- **Status:** Proposed (binds downstream dispatch only after TL harvest/merge)
- **Work order:** P001 (issue #153) · **Register rows:** R-054, S-02, R-028, R-084
- **Binds:** P005 (owner)

## Context

The final handoff (§1 item 6 / L-006) requires the exact names of the "three feature
surfaces/mounts reported as unmounted or not host-integrated" — "do not guess, silently
omit or duplicate them." The register's Part 4 derived them from the live route tree at
base `5067356` cross-referenced with the PR bodies and the PROJECT-STATE C-series harvest,
and each is verifiable in the tree: `apps/web/src/competitions` (C013, PR #143) ships its
barrel, views and the resolvers `resolveCompetitionsHomeExperience` /
`resolveCompetitionDetailExperience`, but **no `apps/web/src/app/competitions/**` page
files exist** (PR #143 Q1: "Who mounts `/competitions` in `apps/web/src/app/**`?"); 
`apps/web/src/body-marketplace` (C014, PR #144) ships browse/detail/request-pretraining/
my-listings route compositions with a full state vocabulary and 11 route tests, but **no
app-router route mounts exist** (PROJECT-STATE C014 harvest: "no app/ route mounts (outside
owned surface)"); `apps/web/src/developers` (C017, PR #135) is mounted read-only at
`apps/web/src/app/developers/**` (5 routes: page, keys, observability, quickstart,
sandbox) with **no server actions or API routes** — PR #135 Q4: "Interactive portal writes
(issue/rotate/revoke keys, run sandbox from the console) need server actions or API routes
with CSRF/idempotency posture — propose a follow-up work item rather than rushing it into
this PR"; PROJECT-STATE C017 harvest: "routes read-only in session posture". The adjacent
C022 disclosure (R-084 — resolvers exported "if the TL wants a UI", no web feature module
built) and the `/tasks` landing-shell finding (L-007) are explicitly recorded as NOT part
of the three.

## Decision

The three surfaces, named exactly (matching the register's Part 4):

1. **S-01 — the competitions web feature** (`apps/web/src/competitions`, Work Order C013,
   PR #143, register row R-054): unmounted — no app-router routes; the exported resolvers
   exist for exactly that mount.
2. **S-02 — the body-marketplace web feature** (`apps/web/src/body-marketplace`, Work
   Order C014, PR #144, register row S-02): unmounted — no app-router routes; the module
   declares itself "one import surface for the route mounts".
3. **S-03 — the developer-portal interactive write actions** (`apps/web/src/developers`,
   Work Order C017, PR #135, register row R-028): mounted but not host-integrated — the
   `/developers/**` routes are read-only in session posture; key issue/rotate/revoke and
   console-triggered sandbox runs have no server actions/API routes with
   CSRF/idempotency posture.

Their **disposition — route mount, nested route, or intentionally non-UI — is delegated
to P005's route inventory** (the App Router vs route-matrix vs C-series-PR-body
reconciliation P005 exists to perform). Constraints the disposition inherits: mounting
uses the shared shell/session/tenant protection and the thin-mount house pattern
(C012/C017/C021 precedent — R-027/R-063); S-03's write actions are integrated in
coordination with P003's transport auth (ADR-P001-08) with CSRF + idempotency posture over
the developer-platform's append-only key lifecycle; R-084 (capability-learning's
conditional UI) stays intentionally non-UI for P-series v1 and P005 records it in the
route inventory so the "three" count stays exact without omission.

## Alternatives considered

1. **Mount the surfaces in P001** — rejected: P001's owned surfaces are
   `docs/architecture-review/*` and `docs/decisions/post-roadmap/*` only; `apps/web/src/app/*`
   is P005's frozen write surface (work-items table).
2. **Name a different count** (e.g. add R-084's conditional capability-learning UI or the
   `/tasks` landing shell as a fourth) — rejected: the final handoff counts exactly three
   surfaces reported as unmounted/unintegrated; R-084 never had a web feature module built
   (a compiler, not a user surface) and `/tasks` is a distinct UX finding (handoff §1 items
   6 vs 7 / L-006 vs L-007). Inflating or shrinking the count would violate "do not guess,
   silently omit or duplicate."
3. **Decide each surface's disposition now** (route vs nested vs non-UI in this ADR) —
   rejected: disposition requires P005's full route-matrix reconciliation; pre-deciding
   per surface without that inventory would be guessing — the exact practice the handoff
   prohibits.

## Consequences

- P005's acceptance maps 1:1 onto this ADR: identify the exact three (done), decide each
  disposition, mount the intended ones with shared shell/session/tenant protection, and
  record R-084's non-UI disposition in the inventory.
- S-03's dependency on P003 transport auth (ADR-P001-08) is now explicit in both ADRs —
  P005 and P003 dispatches must sequence the write-action integration.
- L-006 is pinned to these three names: P005 cannot report route reconciliation complete
  without a recorded disposition for each of S-01, S-02 and S-03.
- No Architecture Lock change (naming and delegation only; no route, contract or lock text
  is altered by this ADR).
