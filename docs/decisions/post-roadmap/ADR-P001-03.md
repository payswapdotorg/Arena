# ADR-P001-03 — C022 proposal envelopes keep full program lineage in v1

- **Status:** Proposed (binds downstream dispatch only after TL harvest/merge)
- **Work order:** P001 (issue #153) · **Register row:** R-075
- **Binds:** P002 (host-side sink wiring), P006 (integrated learning-loop acceptance)

## Context

PR #149 (C022, capability learning compiler) disclosed: "The A021/A022/A023 destinations
are consumed as injected PROPOSAL ports — the real host-side sinks must accept the
envelope shapes (mirror types, pending adapter wiring)" and asked: "should proposal
envelopes carry the full program lineage or a digest reference the host resolves?
(Currently full lineage; sinks may prefer digests.)"

The current shape is `GatedImprovementProposal` (v1): a gated, typed envelope from the
Q1.0 five-condition verdict, carrying the full ImprovementProgram lineage (class,
changed surface, evidence refs, experiment descriptor, adoption verdict) destined for
A021 (Body forge), A022 (compatibility) or A023 (certification).

## Decision

**Keep full program lineage in the envelope for P-series v1.** The P002 host wires the
real destination surfaces (A021 forge / A022 compatibility / A023 certification triggers)
through sink adapters that:

1. accept the full-lineage envelope as the wire shape (the C022 ports' contract stands);
2. record a content digest of the accepted envelope in the destination's own append-only
   history after persisting (digests are an index, not the payload);
3. reconcile the C022 port mirror types against the real destination packages' shapes
   with parity tests at wiring time (same discipline as R-068's mirror confirmations).

## Alternatives considered

1. **Digest-only envelopes** (host resolves lineage by digest lookup) — rejected for v1:
   adds a resolution round-trip at the sink, splits the audit trail (the destination
   would depend on the compiler's ledger to reconstruct provenance), and breaks the
   "append-only, self-describing evidence" posture of lock rule 6.
2. **Both shapes (dual wire format)** — rejected: two formats double the parity surface
   with no current consumer demanding digests.

## Consequences

- Envelopes stay self-describing; each destination's history is independently auditable.
- Larger persisted records — accepted (learning volumes are low by design; Q1.0 gating
  bounds proposal volume).
- If a future consumer needs digest-only exchange, that is a versioned envelope bump
  (`GATED_PROPOSAL_VERSION` exists for exactly this), not a silent change.
- Ungated adoption remains structurally impossible (C022 boundary wall); this ADR changes
  no learning-rights semantics (lock rules 31/32).
