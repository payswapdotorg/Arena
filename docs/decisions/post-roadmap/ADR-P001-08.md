# ADR-P001-08 — Public HTTP/MCP/webhook lifecycle bound to existing C001/ES1.0 and developer-platform contracts

- **Status:** Proposed (binds downstream dispatch only after TL harvest/merge)
- **Work order:** P001 (issue #153) · **Register rows:** R-003, R-032, R-025, R-029
- **Binds:** P003 (owner), P006, P007

## Context

The public-transport questions recur across the C-series. PR #129 (C001) Q3 asked who owns
the HTTP listener (composition root vs adapter binding — resolved host-side by
ADR-P001-07). PR #136 (C019) Q4 recorded the dedupe discipline: "**Webhook event
vocabulary** — event types legitimately recur across lifecycle transitions (e.g.
`escalation.progressed` covers triaged→matching); the at-least-once dedupe discipline is
per-EVENT-ID, not per type." The contracts to bind already exist and are merged:
`packages/escalation` (ES1.0 — `POST /v1/escalations` with durable request id;
idempotency replay of the recorded outcome, key+body mismatch as the typed
`ESCALATION_IDENTITY_CONFLICT`; tenant-scoped reads; the closed 13-type
`ESCALATION_WEBHOOK_EVENT_TYPES` taxonomy with eventId consumer keys), `adapters/escalation`
(signed webhook delivery: HMAC-SHA256 over `<timestamp>.<payload>`,
`x-arena-signature: v1=<hex>`, at-least-once with the stable `x-arena-event-id` dedupe
key, deterministic exponential backoff retry, auditable dead-letter; MCP stdio binding over
the same canonical lifecycle), and `packages/developer-platform` (scoped API keys with the
closed client-application scope vocabulary — `escalations:create`/`escalations:read`/
`observability:read`/`sandbox:run`/`keys:manage`, the "a key can never mint another key"
law, append-only `active → rotated | revoked` key lifecycle, and the sandbox scope
allowlist that denies `escalations:create`). The work-items spec adds the program law:
"Expose existing C001/ES1.0 contracts on a runnable HTTP listener… Do not create an
Epoch-specific API", and R-030 keeps Epoch a reference customer over the derived
EPI1.0→ES1.0 mapping (lock rule 36). R-025 keeps generated JSON contracts for the
developer-platform wire surface as a registration follow-up once the transport stabilizes;
R-029 governs the self-contained `examples/*` posture.

## Decision

**P003 binds the existing contracts to a runnable listener; it designs no new public
semantic surface.**

1. **Surface:** the C001 REST create/status contracts and the MCP tool layer
   (`create-escalation`, `get-escalation-status`) mount at the host boundary
   (ADR-P001-07) as a real HTTP/MCP listener over the SAME canonical lifecycle authority
   and schema — one authority, two transports. No Epoch-specific API exists or is created;
   Epoch consumes through `adapters/epoch-escalation` over this public transport (R-030).
2. **Auth:** developer-platform scoped API keys + tenant policy at the boundary — the
   closed scope vocabulary, the `keys:manage` non-delegation law, the append-only
   rotate/revoke lifecycle, and the sandbox/live environment separation stand as delivered.
3. **Idempotency:** submission replay returns the recorded outcome verbatim with the
   replay marker; an idempotency key paired with a different body yields the typed
   `ESCALATION_IDENTITY_CONFLICT` — the C001 law, preserved unchanged. Correlation and
   causation ids ride the existing envelope conventions.
4. **Webhooks:** at-least-once delivery of the closed 13-type taxonomy, **deduped per
   event id, never per type** (R-032 — types legitimately recur across transitions);
   signing, backoff retry and dead-lettering follow the existing
   `adapters/escalation/src/webhook-delivery.ts` contract (HMAC-SHA256,
   `x-arena-signature`, `x-arena-event-id`).
5. **Errors and health:** a shared error taxonomy — every transport error maps onto the
   existing typed code sets (escalation and developer-platform codes with their
   machine-readable classes) with documented HTTP renderings; health/readiness endpoints
   are exposed at the listener, not improvised per route.
6. **Contracts:** generated JSON contracts for the stabilized wire surface register per
   R-025 (TL-serialized manifest script) at the P003 harvest point — the registration
   follow-up stands.

## Alternatives considered

1. **An Epoch-specific public API** — rejected: the work-items spec forbids it; Epoch is a
   reference customer of the generic Escalation API (lock rule 36, R-030); a second
   public shape would fork authority and schema.
2. **A new P-series transport contract** (redesign request/response/webhook shapes for
   productionization) — rejected: C001/ES1.0 and the developer-platform key model are
   merged, versioned and adversarially tested; the program law is to replace fabrics at
   the boundary, not redesign domain contracts (final-handoff §1.1).
3. **Per-type webhook dedupe** (suppress duplicates by event type) — rejected: event types
   legitimately recur across lifecycle transitions (e.g. `escalation.progressed` covers
   triaged→matching); per-type suppression would drop real distinct events — exactly the
   duplicate-suppression error R-032 records.

## Consequences

- P003 owns `apps/api`, `services/escalation-api/src/http-host/*`, `mcp-host/*` and
  `services/webhook-delivery/*` as wiring surfaces; the domain packages stay untouched.
- P006 drives BOTH clients (generic example + Epoch adapter) through this transport only —
  no in-process service references in acceptance evidence.
- P007 inherits a concrete attack-surface list: API-key leakage, webhook signature
  forgery, replay/redelivery, idempotency races, scope escalation and tenant mismatch
  (each already has an adversarial test precedent in C001/C019 to extend).
- R-025's contract registration and R-029's examples posture remain recorded follow-ups —
  not closed by this ADR.
- No Architecture Lock change (the A2.0 async-operation law — durable identity,
  correlation, idempotency, defined retry/failure — already mandates this posture; the ADR
  binds a specific implementation to it).
