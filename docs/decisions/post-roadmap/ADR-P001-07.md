# ADR-P001-07 — Host owns composition, persistence, jobs, transport, secrets, tenant policy and fail-closed capacity; providers own only primitives behind adapters/hosted/*

- **Status:** Proposed (binds downstream dispatch only after TL harvest/merge)
- **Work order:** P001 (issue #153) · **Register rows:** R-003, R-007, R-008, R-041
- **Binds:** P002, P003, P004, P006

## Context

PR #129 (C001) asked directly: "**HTTP listener ownership** — REST exposure as a deployed
endpoint (host) — should C017 (developer portal) own the composition root that mounts
`EscalationApiService` behind a real HTTP transport, or is an `adapters/escalation` HTTP
binding wanted first?" Around it, the C-series recorded the same split repeatedly: R-007
(the reference fabric's default `RoutingPort` swap to the real C002 service is "P002 host
wiring composes the real routing service; the labelled stub remains the explicit
zero-dependency fallback"); R-041 (C018 `SessionPolicySink`/`ModePolicySink` injected "by
constructor injection at composition" — the P002 host composition root); R-009/R-070
(cross-domain execution stays host-mediated: observed events become authorized commands,
never direct cross-service writes). The final handoff §1 grounds the gap this closes:
L-001 reference fabrics are not the production host (in-memory stores, fake ports,
collecting sinks, in-process composition); L-002 C019 is a reference integration, not a
deployed runtime; L-003 Neon proof incomplete; L-004 R2 lifecycle unproven; L-005 Upstash
PING is not end-to-end coordination proof. The repo already fixes the provider side of the
line: `adapters/hosted/README.md` — "Provider names live HERE and only here", "Fail closed,
never a silent paid fallback" (unconfigured adapters throw `PERSISTENCE_CAPACITY_DISABLED`
before any network call; capacity states AVAILABLE/DEGRADED/EXHAUSTED/DISABLED), "Secrets
stay server-side" (env-var names only, never values), with provider-neutral ports in
`@arena/persistence` enforced by purity test. On the commercial axis, R-008 (C010 PR #131)
keeps the provider posture — merchant-of-record, payout rails, tax, jurisdiction —
BLOCKED-COMMERCIAL under the P008 hard gate, with `DEMO_PROVIDER_POSTURE.executesCustomerMoney
= false` recorded in `adapters/payments/src/demo-provider.ts`.

## Decision

**The HOST owns every platform concern; providers own only primitives.** The P002 host
(`services/runtime-host` + `packages/runtime-host`) is the single composition root and owns:

1. **Composition** — constructing every C-series service and injecting its ports (real
   routing for R-007, policy sinks for R-041, environment runner for R-015, calibration
   reads for R-057); in-memory reference fabrics remain test-only fixtures (L-001 closure).
2. **Persistence** — durable stores for lifecycle/event/job/idempotency records over the
   shared `adapters/hosted/neon-postgres` adapter (L-003's DEMONSTRATED-LIVE evidence is
   P002/P004's to produce).
3. **Jobs** — the shared durable runner of ADR-P001-01 over `services/job-orchestrator`.
4. **Transport mounting** — the host exposes the runtime interface that P003 binds to real
   HTTP/MCP/webhook listeners (complement: ADR-P001-08); neither a web app nor a wire
   adapter is the composition root.
5. **Secrets and configuration** — credentials are read from server-side env vars inside
   `adapters/hosted/*` and injected by the host; no domain service or web surface ever sees
   secret material.
6. **Tenant policy** — tenant isolation and fail-closed authorization enforced at the host
   boundary (lock law: "Tenant isolation and fail-closed behavior belong at service
   boundaries, not only in UI").
7. **Fail-closed capacity** — the FT2.0 posture (probe → DISABLED before network, no
   alternate-route vocabulary, no silent paid fallback) is owned and demonstrated at the
   host, and P004 proves it live for R2/Upstash/Neon (L-004/L-005).

**Providers own ONLY primitives** — storage, object, coordination and (when authorized)
payment rails — behind `adapters/hosted/*` (and `adapters/payments` for the commercial
posture), speaking the provider-neutral ports. Providers never see domain policy, tenant
rules, lifecycle authority or each other; cross-domain execution stays host-mediated
(observed event → authorized command bridge per R-009/R-070).

## Alternatives considered

1. **C017 developer portal owns the composition root** (PR #129 Q3's first option) —
   rejected: the portal is a web feature surface following the M3 thin-mount house pattern
   (R-027); making a Next.js app the composition owner couples production transport
   lifetime and secret custody to a UI deployment and contradicts "tenant isolation and
   fail-closed behavior belong at service boundaries, not only in UI".
2. **Adapter-first HTTP binding** (an `adapters/escalation` listener as the deployed
   endpoint) — rejected: adapters own wire translation (signing, framing, dedupe keys), not
   process lifetime, composition or policy; an adapter-owned listener inverts the approved
   B4 layering and would need its own secret/tenant story.
3. **Per-service autonomous hosts** (each service self-hosts transport + persistence) —
   rejected: N composition roots and N secret stores means divergent restart/recovery and
   fail-closed semantics, contradicts ADR-P001-01's single job runner, and multiplies the
   L-001 replacement the program exists to perform.

## Consequences

- P002's acceptance (migrate from zero, persist, restart-resume, deterministic retries,
  cross-tenant fail-closed) is proven once, at the composition root, for all services.
- P003 binds transport to the host interface; P004 proves provider lifecycle behind the
  same adapters; P006 drives both clients through the composed host — no in-process
  service references in acceptance.
- Provider names/types stay sealed under `adapters/hosted/*` (existing purity law,
  "Provider-specific types stay in adapter/host packages" — operationalized, not changed).
- This ADR does NOT decide R-008: merchant-of-record, payouts, tax and jurisdiction remain
  the release owner's BLOCKED-COMMERCIAL hard gate under P008; no customer-truth payment
  label may be issued before it. The demo provider keeps `executesCustomerMoney = false`.
- No Architecture Lock change (this ADR operationalizes existing lock rules: provider types
  in adapters, tenant isolation at boundaries, fail-closed capacity, append-only history).
