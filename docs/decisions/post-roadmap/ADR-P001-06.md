# ADR-P001-06 — Learning-candidate projection is host-side under P002; producer-package first-party projectors deferred

- **Status:** Proposed (binds downstream dispatch only after TL harvest/merge)
- **Work order:** P001 (issue #153) · **Register rows:** R-076, R-068
- **Binds:** P002 (owner), P006 (integrated learning-loop acceptance)

## Context

PR #149 (C022, capability learning compiler) asked: "**Candidate projection ownership** —
the host projects C008/C009/C013/C014 outputs into the typed candidate view; should each
source package eventually export a first-party projector so the seam is typed at the
producer?" The delivered contract already binds candidates **by digest** to the four source
families — C008 tool-gap / knowledge-patch (`packages/tool-gap`, `packages/knowledge-capture`,
`services/capability-improvement`), C009 escalation-validation
(`packages/escalation-validation`), C013 adversarial research
(`packages/adversarial-evaluation`), C014 pretraining (`services/body-marketplace`) —
through the closed `CANDIDATE_SOURCE_KINDS` vocabulary in `packages/capability-learning`.
The compiler service's `ingestCandidate` (digest-dedup, tenant-scoped) is the single typed
ingestion seam; the projection from each source's own record shapes into that candidate view
is currently the host's job, and no host exists yet (L-001: reference fabrics are not the
production host; `services/runtime-host` is P002's to build). This complements ADR-P001-01
(the learning pipeline's projection jobs run through the shared job runner) and reuses
R-068's discipline (host wiring pins producer-shape mirrors with parity tests against the
real surfaces).

## Decision

**The projection stays host-side under P002.** The P002 host (`services/runtime-host` +
`packages/runtime-host`) builds and owns the projectors that read each source surface's
public outputs (tool-gap staged records, knowledge patches, validation/adjudication
outcomes, adversarial-research byproducts, pretraining/grant records) and construct the
typed `ImprovementCandidate` view for `ingestCandidate`. Rules:

1. The closed `CANDIDATE_SOURCE_KINDS` vocabulary in `packages/capability-learning` stays
   the single typed seam — it is consumer-owned, versioned, and already shipped.
2. Every projected candidate keeps the digest binding to its source record, and the host
   parity-tests its projection against the real producer surfaces at wiring time (the same
   discipline R-068 assigns to P002 for capability-body listing mirrors).
3. Projection runs as registered job kinds on the shared durable runner (ADR-P001-01),
   never as ad-hoc host loops.
4. **Producer-package first-party projector exports are deferred**: no C008/C009/C013/C014
   package grows a projector export in the P-series. A producer that wants a typed
   first-party projector does a versioned package bump when a work order actually owns
   edits to that package — recorded as the explicit follow-up this ADR answers.

## Alternatives considered

1. **First-party producer projectors now** (each source package exports its own projector) —
   rejected: no P-series work order owns edits to `packages/tool-gap`,
   `packages/knowledge-capture`, `packages/escalation-validation`,
   `packages/adversarial-evaluation` or `services/body-marketplace` (the same deferral
   posture as R-005/R-051's mirror hoisting); typing the seam at four-plus producers
   duplicates the closed candidate vocabulary and invites drift, while the consumer-owned
   contract is already versioned and adversarially tested.
2. **Untyped host glue** (plain object mapping at wiring without digest binding or parity
   tests) — rejected: breaks the digest-binding audit posture (candidates are
   content-addressed input views; the Q1.0 gate requires validated evidence digests) and
   reproduces exactly the mirror-drift risk R-068 records.
3. **Defer projection entirely** (no candidates until producers export projectors) —
   rejected: P006's acceptance requires a consent/rights-gated learning candidate in the
   integrated end-to-end loop, so the projection must exist for the acceptance proof.

## Consequences

- P002 delivers the projectors as part of host wiring; the four producer surfaces stay
  code-unchanged (mirrors the ADR-P001-04 precedent of not touching merged, versioned
  contracts mid-program).
- P006's integrated loop can prove candidate → compile → Q1.0 gate → gated proposal without
  any producer-package change.
- The deferred first-party projector option stays visible here and in R-076 — a future WO
  that owns a producer package may adopt it as a versioned export, not a silent seam move.
- Projection correctness rides the parity tests + the compiler's digest dedup; a bad
  projection is detectable as a digest mismatch, not silent data loss.
- No Architecture Lock change (lock rules 31/32 learning-rights/scope semantics are
  untouched; this is a wiring-ownership decision).
